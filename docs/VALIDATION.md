# 0.9.2 preview validation

Validation date: 2026-10-07. This is an experimental preview, not a stable release.

0.9.2 fixes account password expiration, incomplete-install detection and custom RDP listener ports. It records account ownership before/after creation, stores recoverable DPAPI credentials before creating the account and resumes interrupted setup without resetting passwords. Repair installs a versioned anchor while preserving existing service/CLI binaries. The Windows PowerShell 5.1 HTTP decoding fix from 0.9.1 remains included. Setup supports English, Korean and Simplified Chinese, explicit acceptance of the unsupported Windows change and same-owner UAC elevation.

The seat protocol and trilingual web interface remain unchanged. The development PC's installed service is still 0.7.0; its original account and production task have not been repaired with 0.9.2. No disposable Windows test environment was available. Simulated installation/recovery tests and read-only download/setup checks do not claim an actual fresh-machine installation or reboot.

## Completed

- Managed tests: 227 Core and 36 Windows tests passed (`dotnet test AgentSeat.sln -c Release`).
- Bootstrap: 12 offline test groups passed in Windows PowerShell 5.1 (`powershell -NoProfile -File tests/installer/bootstrap.tests.ps1`). They cover HTTP parsing with all three translations, exact release origins, SHA-256/asset digests, corrupt/ambiguous checksums, safe extraction, traversal/ADS/duplicate path refusal, manifests, literal elevation arguments, cancellation, fully configured seat reuse, incomplete seat detection and same-owner checks.
- Recovery: 8 test groups passed in Windows PowerShell 5.1 (`powershell -NoProfile -File tests/installer/recovery.tests.ps1`). Real artifact directories, protected DACLs, atomic journal replacement and owner-bound DPAPI encryption were used. Windows services, local accounts, scheduled tasks, registry reads and API calls were simulated. Cases cover a custom 3397 RDP port, invalid ports, non-expiring passwords, credentials saved before account creation, interrupted service/account/seat registration, service warmup, connection timeout, legacy repair, replaced/deleted accounts, foreign task owners, corrupt credentials and junction refusal. No host services/accounts/tasks, UAC prompts or actual reboot were changed.
- Reboot state: a simulated completed seat with no active session remains configured. The service is Automatic; the anchor task uses a limited interactive owner token, has no login trigger and is disabled until manually requested. Elevated or auto-login-triggered anchor tasks require repair. Actual owner logout/re-login and reboot remain pending.
- The published 0.9.2 native anchor configured a fictitious account in a protected artifact directory without connecting to RDP. The PowerShell recovery reader decrypted its actual DPAPI output and matched the original generated password; reapplying the protected DACL preserved only owner, SYSTEM and administrators access. No Windows account was created.
- Web interface: 12 tests passed (`npm test`). Six cover coordinate scaling, key mapping, wheel/drag actions and serialized input failure/cancellation; six cover locale selection, complete translation dictionaries, placeholder parity, static message keys, safe interpolation, host checks, errors and seat states. Total managed/web/bootstrap/recovery checks: 295, including grouped installer scenarios.
- Chrome displayed the dashboard and live read-only viewer in all three languages. Switching languages preserved the open viewer, text draft and disabled manual-control state; reloading retained the selected language. The Chinese viewer fit a 420-pixel viewport without horizontal overflow. The browser reported no JavaScript warnings/errors during these checks. No input was sent to the seat for localization checks.
- A separately installed `agent-seat` service, account and live desktop worked alongside another desktop service. That service and Terminal Services process IDs and the original settings hashes stayed unchanged during installation.
- CLI observation returned a 1280×800 image from the new user's session. The browser viewer displayed that session; live clicks and right clicks were observed.
- Read-only HTTP integration checks passed for bearer-only ticket issuance, one-use redemption, seat-scoped HttpOnly/SameSite cookies, replay refusal, and refusal to mint tickets with a viewer cookie.
- The published 0.9.2 CLI was tested against the existing service: its MCP server reported version 0.9.2, exposed four tools and returned an image on first observation. Read-only viewer authorization checks also passed. Run the optional checks with `node tests/integration/windows-live.js agent` as the installing owner. Set `AGENTSEAT_CLI` to a published CLI and `AGENTSEAT_EXPECTED_VERSION` to verify its exact MCP version.
- A limited-owner scheduled task launched the repaired RDP anchor from the published binaries, read its protected ProgramData configuration and connected the new desktop at 1280×800.
- Self-contained Windows x64 applications were built with .NET 8.0.31. Release packaging includes TermWrap provenance, original dependency licenses, a file manifest and a ZIP checksum, and rejects private configuration and gaming binaries.

## Pending and known limits

The first installed scheduled RDP anchor could not read its configuration under LocalAppData. The installer and anchor now explicitly use a protected ProgramData directory scoped to the owner's Windows SID. A limited-owner scheduled task passed credential decryption and connected the desktop with that fix. Updating the earlier installed service files and production task on the development PC still requires the owner's Windows administrator approval; the working desktop currently uses the diagnostic task's repaired anchor.

A fresh install on a disposable Windows machine, the guided installer's actual UAC/apply flow, restart/re-login, installation on other Windows builds, and adding a second agent-seat account have not been validated. Recovery simulations cannot establish TermWrap compatibility or first-login behavior on a real machine. Full browser gesture coverage, IME text submission and interaction while another AI is running also need live acceptance testing. Stop the AI before manual control; there is no exclusive human/AI input lock.

TermWrap changes the shared Windows RDP service. Its compatibility depends on the installed Windows build. A separate app name, account and service do not create a virtual machine or security sandbox. See [installation and recovery](INSTALL.md) and [security](../SECURITY.md).
